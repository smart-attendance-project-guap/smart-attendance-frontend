
# Smart Attendance — Frontend

Frontend приложения Smart Attendance — системы автоматизированного контроля посещаемости студентов.

Приложение предоставляет интерфейсы для студентов и преподавателей.

## Технологический стек

- Next.js 16
- React
- TypeScript
- Tailwind CSS
- ESLint
- html5-qrcode

## Структура приложения

### Студенческая часть

| Маршрут | Назначение |
|---|---|
| `/` | Главная страница и выбор роли |
| `/student/login` | Авторизация студента |
| `/student/register` | Регистрация студента |
| `/student` | Личный кабинет и статистика |
| `/student/history` | История посещаемости |
| `/student/attendance` | Отметка посещения и QR-сканер |

### Преподавательская часть

| Маршрут | Назначение |
|---|---|
| `/teacher-login` | Авторизация преподавателя |
| `/teacher` | Кабинет преподавателя |
| `/teacher/lessons` | Список занятий |
| `/teacher/lessons/new` | Создание занятия |
| `/teacher/lessons/[id]` | Просмотр занятия |
| `/teacher/statistics` | Статистика посещаемости |

## Backend

Frontend взаимодействует с локальным Backend через HTTP API.

- Frontend: `http://localhost:3001`
- Backend: `http://localhost:3000`

Основные используемые студенческой частью API:

- `POST /api/auth/register` — регистрация.
- `POST /api/auth/login` — авторизация.
- `GET /api/registration/groups` — получение списка учебных групп.
- `GET /api/attendance/stats` — статистика посещаемости.
- `GET /api/attendance/history` — история посещаемости.
- `POST /api/attendance/:lessonId/mark` — отправка отметки по QR-коду.

Защищённые запросы используют JWT в заголовке `Authorization: Bearer`.

## Установка и запуск

Установить зависимости:

```bash
npm ci
```

Запустить Frontend в режиме разработки:

```bash
npm run dev -- --port 3001
```

Открыть в браузере:

http://localhost:3001

Для остановки сервера нажать `Ctrl + C`.

Backend должен быть запущен отдельно на порту `3000`.

## Проверка проекта

Проверка ESLint:

```bash
npm run lint
```

Проверка TypeScript и production-сборки:

```bash
npm run build
```

## Совместная разработка

- Работа ведётся в общем Next.js-проекте.
- Разработчицы работают в отдельных Git-ветках.
- Изменения общих компонентов, страниц авторизации и стилей согласовываются между участницами.
- Форматы API согласовываются с Backend до интеграции.
- Серверная бизнес-логика и проверки безопасности не реализуются на стороне Frontend.
- В Git запрещено добавлять `.env`, пароли, JWT и другие секретные данные.

## Текущие ограничения и дальнейшая работа

- Отправка координат на Backend требует согласования и интеграции API.
- Проверки геолокации, устройства и лица должны выполняться на стороне Backend.
- Полный сценарий отметки посещения требует интеграционного тестирования с преподавательской частью.
- Необходимо проверить работу камеры и геолокации на реальном мобильном устройстве.
- Для полного отображения пропусков требуется соответствующее API Backend.
